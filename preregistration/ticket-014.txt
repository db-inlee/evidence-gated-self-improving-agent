## 6. Oracle (대칭)

- **대상:**
  - 단계 3에서 고정한 목록 = C4 채택 ∪ SAGE λ1 채택 proposer 후보, 그리고 S0.
  - 그 밖의 후보는 "Oracle 라벨 없음"으로 보고한다.
  - 목록은 `results/ticket-014/stage3-gates.json`(+ sha256)에 단계 4 전에 고정한다.
- **실행:** 대상과 S0 모두 Oracle 600 케이스 × 반복 0, 1, 2다. 반복 r에서 대상과 S0는 같은 LLM seed를 쓴다(same_seed 짝).
- **집계: mean.** 케이스 i의 차이 = (대상 성공 수 − S0 성공 수) / 3이다. 칸 Δ_c와 전체 Δ(칸 동일 가중)는 케이스 차이의 평균이다. majority 집계는 쓰지 않는다. 계획 모의에서 다수결이 천장 칸의 손실을 가렸기 때문이다.
- **구간:** 케이스 단위 칸 층화 paired bootstrap 95% 양측(2.5·97.5 백분위수, 2,000회, seed 0)이다. 칸 구간도 같은 bootstrap의 칸 합에서 낸다.
- **라벨:**
  - **M(margin 부적합, 확인):** 어떤 칸의 상한(97.5 백분위수) < −m(1/20)이다(David 결정, 2026-11-27).
  - **M_point(기술용):** 어떤 칸의 점추정 Δ_c < −m이다. M과 나란히 수를 보고하고, 판정에는 쓰지 않는다.
  - **Useful:** 전체 하한 > ε(1/20)이다. **Clean Useful:** Useful이고 M이 아니다.
  - **라벨 불확실:** M에 대해서는 M이 아니고 어떤 칸 하한(2.5 백분위수) < −m인 경우, Useful에 대해서는 전체 하한 ≤ ε < 전체 상한인 경우다. 각각의 수를 보고한다.
- **계획 모의의 라벨 불확실성**(n_o 100, R 3, mean, 기준선 a). 같은 seed 짝과 독립 짝 사이의 범위로 함께 적는다. 실제 seed 공유의 결합 정도는 재지 않았다.
  - 대표 Useful의 Useful 라벨 불확실: 0.023(same_seed) ~ 0.235(independent).
  - 경험 분포의 효과 라벨 불확실: 0.229 ~ 0.281.
  - 참 −2m 손실의 M 확인: realistic 배치 0.852 ~ 0.865, worst 배치 0.640 ~ 0.693.

## 7. 연구 질문과 판정 규칙 (CD, proposer 후보)

### 7.1 RQ14-1 (주 질문) — C6-IUT가 margin 부적합 후보를 거르는가

- **표본:**
  - C4 채택 후보 n개 중 C6-IUT가 거른 f개, 남긴 n − f개.
  - 각 후보의 M 라벨(6절). k = M인 후보 수, a = 거른 후보 중 M인 수다.
  - C4 채택 후보는 모두 Oracle 대상이므로 라벨이 있다.
- **검정:** 단측 Fisher(초기하) P(X ≥ a), `t009.rq9.fisher_one_sided`. RQ9-1과 같은 함수를 쓴다.
- **판정**(`t009.rq9.rq9_1`의 규칙 그대로, RQ9-1의 margin 판):
  - undecidable: n < 2, 또는 f ∈ {0, n}, 또는 k ∈ {0, n}.
  - not_supported: a / f ≤ (k − a) / (n − f).
  - supported: 방향이 맞고 p < 1/20.
  - direction_only: 방향은 맞지만 p ≥ 1/20.
- **함께 보고:** 2 × 2 표, M 라벨 불확실 후보 수, 불확실 후보를 M이 아닌 쪽과 M인 쪽으로 각각 옮겼을 때의 판정(민감도, 기술용).
  - 주어진 n, f, k에서 달성 가능한 최소 단측 p(a = min(f, k)일 때의 P(X ≥ a))를 기술용으로 보고한다. 판정에는 쓰지 않는다.

### 7.2 RQ14-2 — 모의 예측 검증(판정 없음)

- 판정 기준이 아니다. Ticket 013 계획 모의의 예측과 관측을 나란히 보고한다(David 결정, 2026-11-27).
- **예측:** C6-IUT(기준선 a, n_c 150, m 0.05)의 Clean Useful 손실 = 1 − 대표 Useful 검정력.
  - 검정력은 `results/ticket-013/sim.json`(sha256 02b95b09)의 `decision.a`(gate C6_IUT, n_c 150, m_c 1/20) `useful_power`, 59,352 / 80,000 = 0.7419다.
  - 예측 손실은 20,648 / 80,000 = 0.2581이다.
- **관측:** C4 채택 후보 중 Clean Useful인 u_4개와 그중 C6-IUT가 거른 u개. 관측 손실 u / u_4와 정확 구간(Clopper–Pearson 양측 95%, `exact.clopper_pearson`)을 보고한다.
- **보고:** 구간이 예측값 0.2581을 포함하는지(예 / 아니오). u_4 = 0이면 "정의 안 됨"으로 적는다.
- 지지·불지지 같은 판정 문구는 쓰지 않는다.
- 예측값은 Ticket 013 모의의 대표 Useful 효과 형태(room 셀 +0.10, 나머지 0)에 대한 것이며, 실제 Clean Useful 후보의 효과 분포는 다르다. 구간 포함 여부는 모의 전체의 타당성 판정이 아니라 대략적 일치의 기술이다.

- 명령(`evidencegate.t014.run`): `run --stage N [--max-hours H]`, `preflight --stage N`, `status [--stage N]`, `finalize --stage N`. 단계 0의 proposer는 `evidencegate.t014.propose`, 내보내기·풀 동결·묶음 검사는 `evidencegate.t014.pool`이다.
- `--max-hours N`이면 진행 중인 블록을 끝내고 깔끔히 멈춘다. 재개는 같은 명령이고, 끝난 블록은 건너뛴다. 중간 종료(Ctrl-C, 전원)도 마지막 완료 블록부터 재개한다.
- **중단 규칙:**
  - 환경 지문 불일치(종료 코드 2).
  - 실행 조건 점검 실패.
  - 기존 실행기(`bench_runner`)의 규칙을 그대로 쓴다.
    - 서버 오류는 같은 에피소드를 3회까지 재시도한다. 실패한 에피소드가 연속 3개면 멈춘다.
    - 형식 오류 에피소드 비율이 최근 200개 창(20개째부터 판정)에서 0.05를 넘으면 멈춘다.
  - 이 경우 기록하고 멈춘다. 다시 시작하려면 원인 기록과 David 결정이 필요하다.
