## 4. 게이트, 지표, 결과 라벨

### 4.1 게이트 (proposer 후보, Dev-B N = 420, CD와 ES 각각)

케이스 단위 Δ = 후보 결과 − S0 결과(같은 케이스, 둘 다 반복 0), 값은 −1, 0, +1. 평균 Δ는 Dev-B 420 케이스의 평균, Δ_cell은 그 칸 70 케이스의 평균이다.

| 게이트 | 채택 규칙 | 구현 |
| --- | --- | --- |
| C2 | 평균 Δ ≥ 0 | `gates.gate_c2` |
| C4 | 칸 층화 paired bootstrap(2,000회, 칸마다 칸 크기만큼 복원 추출, seed 0) 평균 Δ의 5번째 백분위수 > 0 **그리고** 평균 Δ > δ(420) | `gates.gate_c4` |
| **C5** | **C4 그리고 모든 칸에서 Δ_cell ≥ −h(70)** | `evidencegate.t009.rq9.cell_condition` |
| C5′(보조) | C2 그리고 모든 칸에서 Δ_cell ≥ −h(70) | 같음 |

- C5 ⊆ C4다. C5와 C4의 차이는 칸 조건 하나뿐이다.
- 칸 조건은 Δ_cell ≥ −h면 통과(비엄격: 같으면 통과), Δ_cell < −h면 기각이다. 유리수로 정확히 비교한다.

### 4.2 h(n_c) (보정 기록만 사용, `evidencegate.t009.rq9.cell_threshold_h`)

> h(n_c) = −q. q는 아래 m 분포의 5번째 백분위수다(선형 보간, `exact.percentile_exact`, 유리수).
> 재표본 b = 1..2000마다 `random.Random(0)` 흐름 하나를 쓴다. 이 흐름은 호출마다 새로 시작한다.
> 1. 보정 S0 반복 0~4에서 순서 있는 쌍 (r, s), r ≠ s를 하나 고른다(`rng.sample(repeats, 2)`). 이 쌍을 여섯 칸에 함께 쓴다.
> 2. 칸 c(`CELLS` 순서)마다 그 칸의 보정 케이스 70개(케이스 키 (family, level, incident_seed) 정렬)에서 n_c개를 복원 추출한다(`rng.choices`).
> 3. Δ_c = Σ(x_r − x_s) / n_c, m_b = min_c Δ_c로 둔다.
>
> 같은 재표본에서 P(m < −h)를 "달성 거짓 기각률"로 기록한다.

- n_c ∈ {70, 4, 8, 16, 34}마다 이 함수를 따로 부른다. 70은 게이트용이고, 나머지는 Budget Curve용이다.
- h 값은 009에서 보정 추가 실행 뒤 이 방법으로 계산해 기록한 `results/ticket-009/thresholds.json`(sha256 `d030b1734811d8a0acc8fdfd198d3d2f0b8ce87c1e81faf322e1f6b1805c3520`)의 값을 쓴다. 다시 계산하지 않는다. 그 계산은 009 최초 사전 등록(태그 `t009-prereg`, sha256 `efb79e1b2a7756298d4ac8bcc641eec33d820234701e01ef492a54b2021c2333`) 아래에서 했다. 실행 전 점검(preflight)에서 이 파일의 sha256을 확인한다.

| n_c | CD h | CD 달성 거짓 기각률 | ES h | ES 달성 거짓 기각률 |
| ---: | --- | --- | --- | --- |
| 70 | 4/35 | 7/200 | 1/35 | 43/1000 |
| 4 | 1/2 | 1/500 | 0 | 49/2000 |
| 8 | 1/4 | 17/500 | 0 | 79/2000 |

### 4.3 지표와 결과 라벨 (Oracle, proposer 후보)

- Oracle Δ = 후보(반복 0) − S0 Oracle 반복 0~4 다수결이다. 전체(300)와 칸별(50)로 낸다. 구간은 칸 층화 paired bootstrap 95% 양측(2.5·97.5 백분위수, 2,000회, seed 0)이다. 구현은 `oracle.estimate`다.
- τ_cell = max(ε, 칸 잡음의 95번째 백분위수)다. 칸 잡음은 S0 Oracle 반복 r마다 나머지 4회 평균을 기준으로 한 |칸 평균(x_r − 기준)|의 다섯 값이다. metric별·칸별로 낸다(`oracle.tau_cells`).
- 지표(v1과 같음): Harmful, Unsupported, Useful, Expected Oracle Gain, False Rejection, Local Harm Acceptance Rate, Useful Acceptance Precision. 구현은 `oracle`, `eval_metrics`다.
- **Local Harm(v1 정의, 함께 보고):** 어떤 칸에서 oracle Δ_cell < −τ_cell(점추정). 구현은 `oracle.local_harm`이다.
- **Severe Local Harm(RQ9-1·RQ9-3의 결과 라벨, `evidencegate.t009.rq9.severe_local_harm`):** 어떤 칸에서 oracle Δ_cell의 95% 구간 상한 < −τ_cell이면 참, 그 밖은 거짓이다.
  - 구간은 칸 안 paired bootstrap이다.
  - 색인은 `exact.stratified_bootstrap_indices([50] * 6, 2000, 0)`에서 그 칸의 블록이다(칸 크기만큼 복원 추출, 공통 난수).
  - 상한은 재표본 합계의 39/40 백분위수(선형 보간)를 칸 크기로 나눈 값이다.
  - 이 라벨은 "확실히 칸을 망가뜨렸는가"를 묻는 한쪽 판정이다. 그래서 불확정 범주를 두지 않는다. §8-13의 양 끝 규칙을 적용하지 않고, 모든 후보가 분모에 들어간다.
- **깨끗한 Useful(RQ9-2):** Useful이 확정 참(구간 양 끝에서 모두 Δ > ε)이고 Severe Local Harm이 거짓인 후보다. Useful이 불확정인 후보는 깨끗한 Useful로 세지 않는다.

## 5. δ(N)

- δ(N) = `exact.null_diff_quantile_exact`(보정 기록 420 케이스 × 반복 5, metric, n_cases = N, q = 0.95, n_boot = 2000, seed = 0)이다.
- 알고리즘: 재표본마다 N개를 복원 추출하고(칸 층화 없음), 반복 쌍 하나를 고른다. |평균 차|의 95번째 백분위수를 낸다.
- N ∈ {420, 24, 48, 96, 204}마다 계산한다. 값은 4.2와 같은 파일(`results/ticket-009/thresholds.json`(sha256 `d030b1734811d8a0acc8fdfd198d3d2f0b8ce87c1e81faf322e1f6b1805c3520`))의 값을 쓴다. 다시 계산하지 않는다. ES의 δ는 계산한 값을 그대로 쓴다.

| N | CD δ | ES δ |

| 420 | 1/35 | 1/140 |
| 24 | 1/12 | 0 |
| 48 | 1/16 | 1/48 |
| 96 | 5/96 | 1/96 |

## 6. 연구 질문과 판정 규칙 (proposer 후보, CD)

판정 문자열은 "지지" / "방향만 일치" / "지지 안 됨" / "판정 불가"다. 코드에서는 `supported` / `direction_only` / `not_supported` / `undecidable`이다. 판정 비교는 따로 적은 경우 외에는 엄격 부등호다. 비엄격 비교는 세 곳이고, 그 자리에 "(비엄격)"으로 적었다:

1. C5·C5′ 칸 조건: Δ_cell ≥ −h(같으면 통과, 4.1)
2. RQ9-2: u / (C4 채택 깨끗한 Useful 수) ≤ 1/5(6.2)
3. RQ9-3: Clopper-Pearson 하한 ≥ 0.10(6.3)

결과가 가설과 다르면 그대로 보고한다.

### 6.1 RQ9-1 (주 질문, 선택적 거르기) — `evidencegate.t009.rq9.rq9_1`

칸 조건은 C4가 받아들인 후보 중에서 심하게 국소적으로 해로운 후보를 **선택적으로** 거른다.

- C4 채택 proposer 후보 전부를 집합 A로 2 × 2 표를 만든다. Severe에는 불확정이 없다.
  - 행: 걸러짐(C4 채택, C5 기각) / 남음(C5 채택)
  - 열: Severe Local Harm / 아님
- 기호: 걸러짐 행의 Severe 수 a, 걸러짐 수 f, Severe 합 k, n = |A|.
- 단측 p = Σ_{x=a}^{min(f,k)} C(k,x)·C(n−k, f−x) / C(n, f)다. 초기하 상단 꼬리이고, `math.comb`와 `Fraction`으로 계산한다.
- 판정:
  - "판정 불가": n < 2, f = 0, f = n, k = 0, k = n 중 하나
  - "지지 안 됨": a/f ≤ (k−a)/(n−f)
  - "지지": a/f > (k−a)/(n−f) 그리고 p < 1/20
  - "방향만 일치": a/f > (k−a)/(n−f) 그리고 p ≥ 1/20
- 해석: C4 채택 후보에서 같은 수를 무작위로 걸러 내면 Severe 비율의 기댓값은 바뀌지 않는다. 이 검정은 "같은 수를 무작위로 걸렀다"는 귀무가설에 대한 것이다. 그래서 "지지"는 "덜 받아들여서 안전해진 것"이 아니라는 근거가 된다.
- v1 Local Harm 라벨로 만든 같은 표와 p를 기술용으로 함께 보고한다.

### 6.2 RQ9-2 (비용) — `evidencegate.t009.rq9.rq9_2`

C5는 깨끗한 유용 후보를 크게 잃지 않는다.

- C4 채택 깨끗한 Useful 후보 중 C5가 기각한 수를 u라 하자.
- 판정:
  - "판정 불가": C4 채택 깨끗한 Useful이 0이거나, C5 = C4(걸러진 후보가 없음)
  - "지지": u = 0이거나 u / (C4 채택 깨끗한 Useful 수) ≤ 1/5(비엄격: 1/5와 같으면 지지)
  - "지지 안 됨": 그 밖
- 기술용으로 함께 보고하는 것:
  - 모든 Useful(확정 참) 기준의 손실 비율과 같은 판정
  - Useful Acceptance Precision과 False Rejection Rate의 C5 − C4 차이

### 6.3 RQ9-3 (v1 발견 재현) — `evidencegate.t009.rq9.rq9_3`

평균 기반 게이트는 심하게 국소적으로 해로운 후보를 받아들인다.

- C4의 Severe Local Harm Acceptance Rate(C4 채택 중 Severe 비율)를 낸다. 그 Clopper-Pearson 정확 양측 95% 하한이 0.10 이상이면(비엄격: 0.10과 같으면 지지) "지지", 아니면 "지지 안 됨"이다. 분모 0이면 "판정 불가"다.
- C2도 같은 방식으로 보고한다(기술용).
- 귀무 라벨률(9절)을 함께 적는다.

### 6.4 RQ9-4 (표본 크기, 기술용, 판정 없음)

- Budget Curve는 Dev-B에서 칸 층화·비복원으로 1,000회 재표본한다(seed 0 흐름 하나, 모든 후보 공통). N ∈ {24, 48, 96, 204}, 칸당 4, 8, 16, 34이고, 전체 N = 420(칸당 70)을 끝점으로 더한다.
- 재표본마다 C2·C4(δ(N))·C5(h(칸당 크기))를 다시 판정하고, C5와 C4의 Severe·Useful 차이를 낸다.
- v1 Budget Curve 출력 경로와 코드는 고치지 않는다. 009 출력은 따로 낸다.
- 사전 기대: 작은 N에서는 h가 커서 C5가 C4와 거의 같아진다.

### 6.5 RQ9-5 (보조 질문, 같은 채택 수의 엄격한 평균 게이트와 비교) — `evidencegate.t009.rq9.rq9_5`

C5는 같은 수를 받아들이는 엄격한 평균 게이트보다 심하게 국소적으로 해로운 후보를 적게 받아들인다.

- C4*: C4 채택 proposer 후보를 Dev-B 평균 Δ 내림차순으로 정렬해 앞의 m = |C5|개를 둔다. 같으면 C4 bootstrap 5번째 백분위수 내림차순, 그다음 candidate_id 오름차순으로 정렬한다. oracle 정보는 쓰지 않는다.
- 기호:
  - D1 = C5 \ C4*, D2 = C4* \ C5(크기 d로 같음)
  - s1, s2는 D1, D2의 Severe Local Harm 수
  - p = Σ_{x=s2}^{min(d, s1+s2)} C(s1+s2, x)·C(2d−s1−s2, d−x) / C(2d, d)(`rq9.fisher_one_sided(a=s2, f=d, k=s1+s2, n=2d)`)
- 판정:
  - "판정 불가": m = 0이거나 C5 = C4
  - "지지 안 됨": Severe(C5) ≥ Severe(C4*)(s1 ≥ s2와 같음)
  - "지지": Severe(C5) < Severe(C4*) 그리고 p < 1/20
  - "방향만 일치": Severe(C5) < Severe(C4*) 그리고 p ≥ 1/20
- 기술용으로 함께 보고하는 것:
  - 개수 규칙의 판정: Severe(C5) < Severe(C4*)면 지지, 아니면 지지 안 됨
  - m, d, s1, s2, D1·D2 목록
  - 깨끗한 Useful 수(C5 대 C4*)
- 해석:
  - RQ9-1은 "같은 수를 무작위로 걸렀다"와 비교한다. RQ9-5는 "같은 수를 평균 Δ 순서로 걸렀다"와 비교한다.
  - "지지"는 칸 조건이 평균을 더 엄격히 보는 것과 다른 정보를 쓴다는 근거다.
  - D1·D2는 RQ9-1 표의 남음·걸러짐 집합의 부분집합이다. 그래서 RQ9-5는 RQ9-1과 독립된 근거가 아니다. 주 질문은 RQ9-1이다.

### 6.6 군집 민감도 (기술용 민감도 판정, 주 판정은 6.1~6.5 그대로)

같은 아이디어의 변형이 풀에 여럿 남으면 후보 효과가 서로 상관된다. 6.1의 Fisher 검정은 후보를 교환 가능한 단위로 보므로 p가 실제보다 작게 나올 수 있다. 판정 규칙은 그대로 두고, 아래 민감도를 함께 보고한다.

  - 나눈 주체: Claude(Claude Code)
  - 방법: 후보마다 S0 대비 변경을 읽고, 같은 아이디어(같은 조건·같은 조치·같은 단계 추가)끼리 묶는다. 009 후보 묶음 파일(`plans/ticket-009b-dedupe-groups.json`)과 같은 방법이다. 게이트·oracle 값은 보지 않는다(그때는 아직 없다).

## 8. 고정 뒤 규칙

- 분석 코드는 본 실행 결과를 보기 전에 고정 커밋을 한다. 그 뒤에는 버그 수정만 허용하고, 고치기 전후 결과를 함께 보고한다.
- 후보 풀은 유효성 검사(Ticket 004 §5)와 중복 제거(2.1의 W, t = 0.55) 외의 이유로 빼지 않는다. 통제 후보·v1 후보·009 후보와 중복이면 남기되 표시한다. 동결 뒤에는 더하거나 빼지 않는다.
- 진행 기준: 호출이 멈췄을 때(풀 40, 포화, 120회 중 어느 이유든) 풀이 N_go = 25 이상이면 그 풀로 본 실행을 한다. 미만이면 "미달"로 기록하고 멈춘다. 비용 상한·잔액 부족·형식 오류율·인증·서버 오류로 멈춘 경우는 이 기준이 아니다. 원인을 바로잡고 같은 설정으로 이어 부르거나, 진행 여부를 사용자가 정한다. 본 실행을 하면 판정 규칙은 그대로 쓴다.
- 실행 중단 규칙은 v1과 같다(`eval_constants`의 값).
  - 형식 오류: 최근 200개 에피소드 창에서 형식 오류가 1회 이상 있었던 에피소드의 비율이 1/20을 넘으면 멈춘다. 20번째 에피소드부터 판정한다.
  - 서버 오류: 같은 에피소드를 3회 재시도한다. 재시도 뒤에도 실패한 에피소드가 연속 3개면 멈춘다.
  - 세션 시작 점검(preflight)과 전원 점검(전원, 덮개, 잠자기 방지) 실패도 중단이다.
- 본 실행은 여러 세션으로 나눠도 된다. 결과는 (케이스, 반복)의 seed로 정해지고 블록 순서는 계획에서 섞여 있다. 그래서 멈춘 시점이 특정 후보에 몰리지 않는다.
