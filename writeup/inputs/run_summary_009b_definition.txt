Run summary 009b definition (Ticket 011 section 6 step 3), fixed before the file is generated
==========================================================================================

Status: run logs, not part of any analysis. Operational numbers for the README (follow-up study,
harness probe limitations). They never enter a verdict. No new runs, no re-analysis.

Honesty note: several of these numbers were already seen before this definition was written
(the 009 shortfall and the 009b proposer numbers are stored in committed files; the same-seed
agreement 575/600 was computed once in report 2026-11-10-02; the 009b session log was read while
the run was in progress). This definition fixes how each value is read or counted. It is not a
blind definition, and no value is tuned after this commit.

Output: writeup/inputs/run_summary_009b.json and run_summary_009b.json.sha256 ("sha256  name").
Sorted keys, no generation time; the same inputs give the same bytes. The generator only reads
its inputs and refuses to write if a pinned input sha256 below differs. It writes no CD, no ES
and no action kinds.

Kinds for writeup/generated/values.json: every counted or read value is "run"; every input path,
sha256, commit, tag and free-text status is "provenance".

Shared rule (same as the v1 run summary, src/evidencegate/run_summary.py, unchanged):
- An episode runs from started_at to started_at + duration_s.
- An idle span is a stretch of at least IDLE_GAP_S = 60 s (evidencegate.eval_constants) with no
  episode running, after merging overlapping episodes (function idle_gaps).
- Records are read with EpisodeStore(path, repair=False). Times are reported in UTC, seconds.
